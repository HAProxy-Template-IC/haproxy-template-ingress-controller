# Changelog

All notable changes to the Haptic Helm Chart will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

For controller changes, see [Controller CHANGELOG](../../CHANGELOG.md).

## [Unreleased]

### Fixed

- Per-Gateway pod-port allocation is now a pure hash of the (Gateway, port) key instead of read-back from committed Services. The read-back design could permanently bind two Gateways to one pod port (plaintext requests answered with TLS alerts by the neighbour's ssl bind) or oscillate Service targetPorts indefinitely under Gateway churn, because the cluster cache lags the allocator's own output. Ports now come from a deterministic sha256 slot in [18000, 19000) (`perGatewayPodPortBase`/`perGatewayPodPortRange`), so allocations are stable across renders, replicas, and restarts; existing installs may see per-Gateway target ports move once on upgrade (internal pod ports only — LB IPs and listener ports are unaffected).

- The controller's startup probe is now enabled by default. Controller startup includes running the config's embedded `validationTests` (which grow with the chart), so time-to-first-healthy can exceed the liveness budget on slow or contended nodes — the liveness probe then kills the controller mid-initialization and the pod crash-loops forever ("Liveness probe failed: 503"). With the startup probe on (30 × 10s budget), liveness and readiness only engage after initialization completes.
- The default Coraza WAF directives were silently detection-only: `SecRuleEngine On` was placed BEFORE `Include @coraza.conf-recommended`, and that include itself sets `SecRuleEngine DetectionOnly`, overriding the earlier `On` (directives are processed sequentially). Rules — including per-Ingress `modsecurity-snippet` rules — matched and logged but never blocked (no 403). The default now puts `SecRuleEngine On` after the includes. Operators with custom `spoaHub.plugins.coraza.directives` should check their own ordering.
- Backend-level annotation directives (e.g. haproxytech/nginx/haproxy-ingress rate-limiting `stick-table`/`track-sc0`/`deny` and their `# library/…` provenance comments) now render indented to 2 spaces like the rest of the backend body, instead of flush-left at column 0. The `backend-directives-*` extension point was the only backend-body injection point missing `| indent(2, true)` (the other section-body globs already had it; map/global/backends globs correctly emit at column 0). Cosmetic only — HAProxy is whitespace-insensitive.
- The `# Path matching: …` and `# Extension point: advanced matchers …` comments in the frontend routing logic no longer render fused onto an adjacent directive/comment line (a whitespace-control artifact at the snippet-render boundaries). Cosmetic only.
- `host.map` no longer contains dead regex entries and a stray `# gateway/map-host-regex-gateway` provenance marker. The exact-host `render_glob "map-host-*"` was over-matching the wildcard-regex snippets (which share the `map-host-` prefix), duplicating their `^…$` entries (never matched by an exact `map()` lookup) and their comment into `host.map`. The regex snippets are renamed to the `map-hostregex-*` extension point so the two no longer collide; `host-regex.map` is unchanged. Operator-defined `map-host-*` snippets are unaffected.
- Several map-file headers (`host.map`, `host-regex.map`, `path-regex.map`, `weighted-multi-backend.map`) no longer render their leading comment fused onto the first provenance marker (leading-strip `{{-` artifact).
- Removed an inaccurate `# Note: dynamic-cookie-key would be set by base template …` comment from haproxytech cookie-persistence backends — no `dynamic-cookie-key` is ever emitted, so each HAProxy instance derives its own cookie key (the docs example and note are corrected to match).

### Changed

- The generated `haproxy.cfg` comments are now terse: the multi-paragraph rationale that was inlined into the routing logic, `timeout connect`/`option redispatch`, h2c detection, and the gRPC default-backend is condensed to one or two lines plus a link to the [Base library docs](https://haproxy-haptic.org/helm-chart/latest/libraries/base/). This shrinks the rendered config (the routing-logic comment block was previously emitted in full in each of the three frontends) without changing any directive. The redundant second `path_match_qualifier` re-parse is now emitted only when advanced matchers (gateway library) are present.
- Verbose comment headers across the generated `.map` files (spoa-hub external-auth / Coraza maps, base `body-size`/`reqhdr-*`/`path-rewrite` maps) and several in-config rationale blocks (gateway SNI dispatch / 421 misdirected-request, SSL-passthrough SNI routing, BackendTLSPolicy fail-closed) are condensed to 2-3 lines plus a docs link. Implementation/conformance detail moved to non-rendered template comments or the library docs; no rendered directive changed.
- Runs of blank / whitespace-only lines in the generated `haproxy.cfg` (left behind by empty extension-point snippets and render boundaries) are collapsed to a single blank line via a post-processing pass. Purely cosmetic — HAProxy ignores blank lines.
- The deployed DataPlane API now uses relative storage dirs (`maps`/`ssl`/`general`) resolved against the dataplane container's `workingDir` (the HAProxy base dir), instead of absolute paths. This makes it address runtime maps/certs by the same relative identifier HAProxy uses (from `default-path origin`), so map content changes apply via the runtime API without a reload. Storage files still land in the same absolute dirs; the `dataplane.mapsDir`/`sslCertsDir`/`generalStorageDir` values are unchanged and remain authoritative for the controller's validation path derivation.
- The auto-generated DataPlane API password (`credentials.dataplane.password` left empty) is now a **random** 32-char value instead of a deterministic hash of the release name and namespace. The Dataplane API is HAProxy's runtime control plane over plain HTTP, so a credential derived from public, guessable inputs was a weakness. Existing installs are unaffected — the password is preserved from the existing Secret via `lookup` on `helm upgrade`. **GitOps note:** under ArgoCD/Flux (rendering without cluster lookup), an empty password now regenerates on every sync; set `credentials.dataplane.password` explicitly (e.g. via a SealedSecret) for those setups.
- The validating admission webhook now provisions its own **self-signed TLS certificate by default** (no cert-manager required): `webhook.certManager.enabled` defaults to `false`, and the chart generates a long-lived self-signed cert (`webhook.selfSigned.certValidityDays`, default 10y) that is reused across upgrades (no churn). cert-manager stays opt-in (`webhook.certManager.enabled=true`, recommended for production / automatic rotation); the manual `webhook.caBundle` path is unchanged. Admission validation now works out of the box instead of requiring cert-manager. The self-signed cert is **not auto-rotated** — rotate via cert-manager, or manually by deleting the Secret and running `helm upgrade`. **Upgrade note:** a release that used the previous cert-manager default holds a cert-manager-created webhook Secret (`<fullname>-webhook-cert`) that lacks Helm ownership metadata; because the self-signed default reuses the same Secret name, `helm upgrade` will refuse to adopt it. Before upgrading, either keep cert-manager (`--set webhook.certManager.enabled=true`) or delete the old Secret so the chart can recreate it (`kubectl delete secret <release>-webhook-cert -n <namespace>`).
- `proxy-body-size` (nginx-ingress and haproxy-ingress) is now enforced by a shared resource-agnostic frontend rule reading per-backend limits from a new `body-size.map`, instead of an `http-request deny` inside each backend. Adding or changing a body-size limit is now a map-only, reload-free update; the annotation and the 413 behaviour are unchanged.
- Upstream request-header overrides — `haproxy.org/set-host`, and nginx-ingress `upstream-vhost` / `x-forwarded-prefix` / `connection-proxy-header` — are now applied by shared resource-agnostic frontend rules reading per-backend values from new `reqhdr-host.map` / `reqhdr-xfwd-prefix.map` / `reqhdr-connection.map`, instead of per-backend `http-request set-header`. Changing a value is a map-only, reload-free update; behaviour and the config-injection guard are unchanged.
- `rewrite-target` (nginx-ingress and haproxy-ingress), when the value is a literal path with no `$N`/`\N` capture, is now applied by a shared frontend `set-path` rule reading `path-rewrite.map`, instead of a per-backend `http-request replace-path`. Capture/regex rewrites still render as `replace-path` in the backend. Literal-rewrite changes are now map-only and reload-free.
- `ssl-redirect` / `force-ssl-redirect` (nginx-ingress and haproxy-ingress) now register their hosts into the shared host-keyed `ssl-redirect-<code>.map` (the same map haproxytech already uses), instead of emitting a per-ingress inline-ACL `http-request redirect`. ssl.yaml emits the single map-based redirect rule, so adding/removing a redirected host is a map-only, reload-free update. Behaviour and status codes are unchanged.
- Host-keyed redirects — `redirect-to` (haproxy-ingress), `request-redirect` (haproxytech), and `permanent-redirect`/`temporal-redirect` (nginx-ingress) — are now applied by a shared resource-agnostic frontend rule reading per-host target+code from new `redirect-loc-<code>.map` files, instead of a per-ingress inline-ACL `http-request redirect`. Adding or changing a host redirect is now a map-only, reload-free update; the annotations, status codes, and config-injection guards are unchanged.
- HSTS (`hsts` / `hsts-max-age` / `hsts-include-subdomains` / `hsts-preload`, nginx + haproxy-ingress) is now applied by a single shared resource-agnostic rule reading the per-host `Strict-Transport-Security` value from a new `hsts.map`, instead of a per-ingress `http-response set-header`. Changing an HSTS value is now a map-only, reload-free update; the header value and `ssl_fc` gating are unchanged, and `hsts-max-age` gains a config-injection guard.
- The remaining conditional redirects are now map-driven and reload-free too: `app-root` (nginx + haproxy-ingress → shared `app-root.map`), `auth-tls-error-page` mTLS error redirect (nginx + haproxy-ingress → shared `mtls-error.map`; the cert-passthrough set-headers stay inline), `from-to-www-redirect` (nginx → `from-to-www.map`), `default-backend-redirect` (haproxy-ingress → per-code `default-backend-redirect-<code>.map`), and `ssl-redirect-port` (haproxytech → per-code `ssl-redirect-port-<code>.map`). Each replaces a per-ingress inline-ACL redirect with a single shared rule reading the map; the gates (`{ path / }`, `ssl_c_verify`, scheme split, `!backend_name`, explicit port) and status codes are unchanged. `app-root` and `auth-tls-error-page` values now also get a config-injection guard they previously lacked.
- Default `haproxyVersion` is now `3.4` (was `3.2`); the controller and HAProxy pod images default to the HAProxy 3.4 series. Added `3.4` to `haproxyPatchVersions` (and a pending `haproxyEnterprisePatchVersions` entry). Override `haproxyVersion` to stay on an older series.
- gateway library: the cluster-wide `configmaps` watch now defaults to `store: on-demand` (CachedStore) instead of `full`. It is only read by name for BackendTLSPolicy CA bundles and never iterated, so keeping every cluster ConfigMap body resident was pure overhead; on-demand keeps just references resident and fetches bodies live on access (matching the `secrets` watch).
- Template libraries (`gateway`, `nginx-ingress`, `haproxy-ingress`, `haproxytech`) are now packaged as conditional **subcharts** instead of files bundled into the parent. A release stores only the source of the libraries it enables — disabled libraries are pruned from the Helm release Secret — so an install with all libraries enabled no longer exceeds the Kubernetes 1 MiB Secret limit (it previously did, breaking `helm install`). No values changes: the same `controller.templateLibraries.<x>.enabled` flags gate subchart inclusion, and the rendered `HAProxyTemplateConfig` is byte-identical. `base`/`ssl`/`ingress`/`ingress-annotations-compat`/`spoa-hub` remain in the parent.

### Added

- Template libraries can now declare default `templatingSettings.extraContext` values (top-level `templatingSettings.extraContext` in the library file / `_index.yaml`). They merge into the rendered config at the lowest precedence, so an operator override via `controller.config.templatingSettings.extraContext.<key>` still wins. Used for library-global tunables that mirror an upstream controller's global ConfigMap setting.
- nginx-ingress library: `nginxHttpRedirectCode` extraContext var (default `308`) sets the status code for `ssl-redirect` / `force-ssl-redirect` HTTP→HTTPS redirects — the equivalent of ingress-nginx's global `http-redirect-code`. Override via `controller.config.templatingSettings.extraContext.nginxHttpRedirectCode` (valid: 301, 302, 303, 307, 308).
- `monitoring.prometheusRule.defaultRules` now ships four more default alerts (each individually toggleable): `configRejected` (a config change refused by the validation gate — the latest change is not live), `haproxyPodsRejected` (discovered HAProxy pods refused admission, e.g. a version mismatch), `noHAProxyPods` (no HAProxy pods to manage — no config reaches the data plane), and `criticalEventsDropped` (event-bus drops — reconciliation work lost). The underlying metrics already existed and the docs already recommended alerting on them; the chart now enables the rules by default.
- nginx-ingress library: `mirror-target` — fire-and-forget request mirroring via the spoa-hub mirror plugin (reuses the Gateway RequestMirror machinery; each mirror-target Ingress gets its own mirror slot — capped at `spoaHub.mirrorStaticMinSlots` — host-gated, with `option http-buffer-request` so request bodies reach the plugin). Only the URL authority of the nginx template is used as the mirror target; `mirror-host` and `mirror-request-body: off` need a mirror-plugin change and are unsupported. Requires `spoaHub.plugins.mirror` enabled (else the render fails with an actionable message).
- nginx-ingress library: `session-cookie-domain` (→ cookie `domain`), and `session-cookie-max-age` / `session-cookie-expires` (→ cookie `attr Max-Age=<s>` — the browser-facing cookie lifetime, not HAProxy's internal `maxlife` stickiness window; HAProxy can't compute an absolute `Expires` date so both map to `Max-Age`; `max-age` takes precedence). (`affinity-mode`, `conditional-samesite-none`, and `change-on-failure` remain unimplemented — no faithful HAProxy CE mapping.)
- nginx-ingress library: `auth-secret-type: auth-map` (Secret data keys are usernames, values are password hashes — alongside the existing `auth-file` htpasswd layout), `proxy-next-upstream`/`-tries` (retry conditions → HAProxy `retry-on` + `retries`; `non_idempotent` and `proxy-next-upstream-timeout` have no CE equivalent and are ignored), `limit-rate`/`limit-rate-after` (per-connection download throttle via `filter bwlim-out` + `set-bandwidth-limit`), and `proxy-redirect-from`/`proxy-redirect-to` (rewrite upstream `Location`/`Refresh` headers via `http-response replace-header`; the `default` mode is unsupported and warns).
- Gateway API `TCPRoute` (L4): a Gateway listener with `protocol: TCP` now forwards raw TCP on its port to the attached TCPRoute's backend Service via a dedicated `mode tcp` frontend → `mode tcp` backend (single-backendRef; weighted splitting and TCPRoute status conditions not yet emitted). The `tcproutes` watch is added only when the (Experimental-channel) TCPRoute CRD is present on the cluster, so Standard-channel installs are unaffected.
- Gateway API HTTPRoute/GRPCRoute session persistence (GEP-1619, `type: Cookie`): `spec.rules[].sessionPersistence` maps to HAProxy `cookie <sessionName|SESSION> insert indirect nocache dynamic [maxlife][maxidle]` + `dynamic-cookie-key` on the referenced backend (per-pod affinity). `type: Header` deferred.
- Gateway API HTTPRoute `retry` (`spec.rules[].retry` → backend `retries` + `retry-on <codes>`; exponential backoff not expressible), per-listener TLS options (GEP-2907 `listeners[].tls.options` → per-bind `ssl-min-ver`/`ssl-max-ver`/`ciphers`/`ciphersuites`), and BackendTLSPolicy `validation.subjectAltNames` (first Hostname-type SAN drives `verifyhost`; URI SANs deferred).
- haproxy-ingress library: `oauth: oauth2_proxy` — a convenience that desugars onto the existing external-auth machinery (no new SPOA plugin). The oauth2-proxy address is derived from the Ingress's own `oauth-uri-prefix` path (default `/oauth2`); it sets `auth-url` (`/oauth2/auth`), `auth-signin` (`/oauth2/start?rd=%[path]`), `auth-method HEAD`, and forwards `oauth-headers` (default `X-Auth-Request-Email`) on success. `auth-url` takes precedence when both are set. Emits an `http://` auth URL, so the spoa-hub external-auth plugin must run with `allow_plaintext` for a plain-HTTP in-cluster oauth2-proxy.
- haproxy-ingress library: `rewrite-target` (path rewriting with nginx-style `$N`→`\N` capture translation), rate limiting (`limit-rps`, `limit-rpm`, `limit-whitelist` — advertised but previously emitting no config), `proxy-body-size` (413 over limit), `ssl-ciphers-backend`/`ssl-cipher-suites-backend` (per-backend TLS cipher control), `agent-check-port`/`-addr`/`-interval`/`-send` (auxiliary agent health check), `default-backend-redirect`/`-code`, `server-alias`/`server-alias-regex` (extra hostnames → primary host's backends), and `config-frontend`/`config-global`/`config-defaults` (raw directive injection into those sections).
- nginx-ingress library: `upstream-vhost`, `x-forwarded-prefix`, `connection-proxy-header` (upstream request-header rewrites), `limit-rpm`/`limit-whitelist` (rate limiting), `session-cookie-secure`/`session-cookie-samesite` (cookie attributes), `permanent-redirect-code`/`temporal-redirect-code` (redirect status override), `from-to-www-redirect`, backend TLS to upstream (`proxy-ssl-secret`/`proxy-ssl-verify`/`proxy-ssl-name`/`proxy-ssl-server-name`/`proxy-ssl-ciphers`/`proxy-ssl-protocols`), `proxy-cookie-domain`/`proxy-cookie-path` (downstream Set-Cookie rewrite), `server-alias`, `default-backend` (per-Ingress catch-all Service), and `satisfy` (`any` OR-combines IP allow-list with auth).
- haproxytech library (`haproxy.org/`): `rate-limit-whitelist` (CIDRs exempt from the rate-limit deny), `ssl-redirect-port` (HTTP→HTTPS redirect to an explicit port), and the previously silent-no-op `check`/`check-interval`/`scale-server-slots` are now honored.
- `spoaHub` values block and a conditionally-rendered SPOA hub sidecar (hub plus seven plugin libraries: mirror, coraza, external-auth, fingerprinting, maxmind, otel, sso-auth), auto-rendered when any plugin is enabled. A `spoa-hub` template library wires the HAProxy-side SPOE config (`backend spoa-hub`, frontend filter, `spoe.conf`), and the controller delivers the hub's runtime `config.toml` via the dataplane API so the file-watching hub reloads without a restart.
- The `HAProxyTemplateConfig` admission webhook now also runs the config's embedded `validationTests` (the same suite the controller's load gate runs), so a config whose tests fail is denied at `kubectl apply`; its `timeoutSeconds` is `10` to give the suite headroom on top of render + `haproxy -c`. `failurePolicy: Ignore` is unchanged, so an unreachable or slow webhook admits-with-warning and the load gate still enforces.
- `controller.validators` block and a validator sidecar (same image, `--validate-socket` mode) consulted by the admission webhook, with readiness/liveness probes guarding the socket. Auto-enabled with the spoa-hub sidecar.
- Gateway API support for `RequestMirror` (via `spoaHub.plugins.mirror`, auto-enabled with the gateway library), `SupportTLSRoute`, `SupportGatewayStaticAddresses` (per-Gateway LoadBalancer Service, multi-IP via MetalLB annotation), `SupportGatewayInfrastructurePropagation` (per-Gateway marker Service carrying `spec.infrastructure` metadata), `SupportListenerSet` routing, and GEP-91 frontend client-cert validation (verify mode, per-reason status, `InsecureFrontendValidationMode` condition).
- nginx-ingress and haproxy-ingress libraries wire the external-auth annotation family (`auth-url`, `auth-signin`, `auth-method`, `auth-headers-request`, `auth-headers-succeed`/`-fail`, client-mTLS `auth-tls-*`) to the SPOA hub's external-auth plugin, plus the Coraza WAF annotations (`/waf`, `modsecurity-snippet`) with per-resource opt-in and a `default-on` dispatch mode.
- `nginx-ingress` template library for `nginx.ingress.kubernetes.io/*` annotation compatibility (disabled by default), and a new `ingress-annotations-compat` scaffold library (level 2.5) providing shared Ingress vendor-annotation macros (SSL passthrough, CIDR access control).
- `https-bind-extra-*` extension point for Gateway HTTPS listeners on non-default ports; SSL-passthrough SNI matcher now supports wildcard listener hostnames.
- HTTPRoute `RequestRedirect` with scheme and port both unset now preserves the inbound listener port in `Location`; per-listener-port routing isolation via a `:<port>` host-map fallback.
- The chart-static `haptic-haproxy` LoadBalancer Service is now rendered via the controller's `spec.k8sResources` (SSA with an `OwnerReference`), folding non-default Gateway listener ports into the same Service.
- `haproxy.initialConfig` values key for the HAProxy bootstrap ConfigMap; `controller.config.dataplane.{configPublishInterval,reloadVerificationTimeout,syncTimeout}` tunables (commented out by default).
- `controller.config.extraContext.hardStopAfter` (default `10s`) emits `hard-stop-after` so old workers don't accumulate across reloads.
- Always-on local `peers localinstance` section (`localpeer local`, listening on a unix socket so it can never collide with a frontend/Gateway listener bind) so stick-tables that opt in survive reloads; `haproxy.org/rate-limit-*` and `nginx.ingress.kubernetes.io/limit-rps`/`limit-connections` counters now persist across config reloads (replicated old-worker→new-worker, per-pod, no cross-replica sync) instead of resetting and granting every client a fresh budget.
- `haproxy.dataplane.aclFormat` to override the dataplane access-log format (adds per-request μs timing); test profiles opt in.
- ClusterRole now grants `customresourcedefinitions` get/list/watch (typebootstrap schema resolution) and, when the gateway library is enabled, cluster-wide `services` write verbs; a namespace-scoped Role grants `services` for same-namespace per-Gateway Services. New `extraContext` keys `controllerNamespace` and `haproxyPodSelector`.
- HAProxy NetworkPolicy opens to all TCP ports when `haproxy.networkPolicy.allowExternal: true` so dynamic Gateway listener ports work; restrictive mode unchanged.

### Security

- CIDR-list annotations (allowlist/denylist source ranges, rate-limit/connection whitelists, `satisfy` whitelist) are now validated against a strict IP/CIDR charset before being interpolated into HAProxy `src` ACLs. Previously a crafted annotation value containing a newline or space could inject arbitrary HAProxy directives into the rendered config (config injection passing `haproxy -c`). The nginx `satisfy` auth realm is likewise rejected if it contains a double-quote or newline.
- Single-value annotations interpolated onto an HAProxy config line — nginx `upstream-vhost`/`x-forwarded-prefix`/`connection-proxy-header` (header values), `proxy-ssl-name`/`proxy-ssl-ciphers`/`proxy-ssl-protocols`, and `proxy-cookie-domain`/`-path` — now reject control characters (and embedded spaces for single-token fields) via a shared `ValidateConfigValue` guard, closing the same newline-injection vector.

### Fixed

- Gateway API `validationTests` that assert experimental-channel HTTPRoute features (`sessionPersistence`, `retry`) are now skipped unless the new `controller.templateLibraries.gateway.experimentalChannel` value is set true. As of Gateway API v1.6 the Standard and Experimental installs ship an identical CRD set (TCPRoute, ListenerSet, UDPRoute et al. graduated to Standard), so the difference is field-level additions to HTTPRoute that Helm `.Capabilities` cannot detect — a GVK-presence check (e.g. TCPRoute) no longer distinguishes the channels and wrongly enabled these tests on Standard-channel clusters, where the asserted directives are correctly absent; with the fatal load gate that crash-looped the controller. Operators on the Experimental channel set the flag to keep the self-tests; offline CI sets it to exercise them against the experimental schemas.
- The Gateway API TCPRoute watch is now version-adaptive (`gateway.networking.k8s.io/v1` on v1.6+, `v1alpha2` on older releases), selected from the served CRD version; the feature is wired whenever the TCPRoute CRD is served at either version and stripped when it is served at neither.
- The bundled `validationTests` now pass in **any** release namespace, not only `haproxy-haptic`/`default`. The `_global` SSL fixture's `default-ssl-cert` Secret is now rewritten to the same namespace `default.pem` looks it up in (`default_ssl_cert_namespace`, i.e. the release namespace); previously it hardcoded `haproxy-haptic`/`default`, so in any other namespace the default-cert render failed and most tests failed. Previously latent (the suite was only run offline in the `default` namespace and non-fatally at controller startup); it matters now that the controller runs `validationTests` fatally on load.
- spoa-hub/haproxy-ingress coraza WAF `validationTests` that consume `nginx.ingress.kubernetes.io/*` annotations are now skipped when the `nginxIngress` library is disabled, instead of shipping and failing at runtime. The coraza plugin auto-enables whenever `haproxyIngress` (or `nginxIngress`) is on, so a common profile — `haproxyIngress` enabled, `nginxIngress` disabled — loaded the spoa-hub library and its coraza tests but not the nginx-ingress scan that produces the maps those tests assert on, surfacing 11 spurious `validationTests failed` errors on every config load. Gated via a new `haptic.nginxIngress.disabled` helper.
- nginx-ingress library: `ssl-redirect` now emits a **308** redirect (was `301`), matching ingress-nginx — which sends both `ssl-redirect` and `force-ssl-redirect` via its `http-redirect-code` (default 308). 308 preserves the request method on POST where 301 may downgrade it to GET. Override the code with the new `nginxHttpRedirectCode` extraContext var.
- The chart now auto-wires the `spoa-hub` validator: when the spoa-hub sidecar and the validator sidecar are both enabled, `spec.validators` gains a `spoa-hub` entry routing the rendered `general/spoa-hub-config.toml` to the `--validate-socket` sidecar, so admission-time WAF/TOML validation (ADR-0007) works without hand-adding `controller.validators.entries`. An operator-provided `spoa-hub` entry still takes precedence.
- The chart now fails fast at install with actionable guidance when `webhook.certManager.enabled=true` but the cert-manager CRDs are absent on the target cluster, instead of leaving the controller pod stuck in `ContainerCreating` waiting for a webhook-cert Secret that is never created. The check is liveness-gated, so `helm template` and offline linting are unaffected.
- `haproxy.org/check`, `haproxy.org/check-interval`, and `haproxy.org/scale-server-slots` are now honored instead of being silently ignored: `check: "false"` emits `default-server no-check`, `check-interval` emits `inter <duration>`, and `scale-server-slots` now drives the pre-allocated server-slot count (the value was computed but never passed to the backend renderer).
- haproxy-ingress `maxconn-server`, `maxqueue-server`, `initial-weight`, `backend-check-interval`, `health-check-port`, `health-check-fall-count`, and `health-check-rise-count` are now honored: each emits its `default-server` keyword (`maxconn`/`maxqueue`/`weight`/`inter`/`port`/`fall`/`rise`). The values were validated and stored but never rendered onto the server line.
- haproxytech IP access control is now keyed on the canonical upstream annotations `haproxy.org/allow-list` / `haproxy.org/deny-list` (with the deprecated `haproxy.org/whitelist` / `haproxy.org/blacklist` aliases honored as a fallback). The library previously bound the non-existent one-word `allowlist`/`denylist` keys, so the real annotations emitted no ACL.
- haproxy-ingress `limit-rps`/`limit-rpm` rate-limit stick-tables now carry `peers localinstance`, so per-source counters survive HAProxy reloads instead of resetting to zero (matching the haproxytech and nginx-ingress libraries).
- haproxy-ingress honours the deprecated `whitelist-source-range` annotation as an alias of `allowlist-source-range` (ignored when the canonical key is also set, matching upstream); it was previously read by no snippet.
- nginx-ingress `session-cookie-hash` now emits a warning comment when set instead of being silently ignored — HAProxy uses `dynamic` cookies whose hash is not operator-selectable, so `md5`/`sha1`/`index` cannot be honoured. The `_index` "supported" claim is corrected accordingly.
- `defaults` block now sets `option redispatch` and `base.yaml` filters out not-ready / terminating endpoints, eliminating the single-replica rolling-restart 503 windows.
- Reserved-slot server addresses are now config-driven across reloads (removed the HAProxy server-state-file machinery); placeholders moved to the unroutable `192.0.2.1:1` sentinel. See [ADR-0011](../../docs/adr/0011-no-haproxy-server-state-file.md).
- `haproxy.dataplane.validateConfig: false` now actually skips the dataplane's `haproxy -c` (the flag was misplaced under `haproxy:` instead of `haproxy.reload.*`), cutting raw-config push time ~130ms → ~18ms.
- Named Service-port references (`port.name`) in Ingress / HTTPRoute / GRPCRoute and SSL-passthrough backends now resolve to the correct numeric port via a shared `ResolveServicePort` helper that fails loud on unresolvable input (was silent 503s / empty backends).
- `haproxy-ingress.github.io/path-type` annotation now actually routes (fixed missing `BACKEND:` qualifier, missing macro call on the regex renderer, and missing wildcard-host normalization).
- Gateway TLS-cert registration treats unspecified `tls.mode` as the spec default `Terminate` (was silently skipping the listener); BackendTLSPolicy with no resolvable CA now returns 503 instead of downgrading to plaintext; TLSRoute status patches target `gateway.networking.k8s.io/v1`.
- Per-resource feature maps (`auth-*`, `coraza-app`, `waf`) are keyed by resource identity, fixing silent auth/WAF skips on regex, prefix, and wildcard-host paths; `modsecurity-snippet` rules are path-scoped per Ingress.
- HAProxy-Ingress / nginx-ingress `auth-headers-*` directives now emit into both the HTTP/1.1 and HTTP/2 cleartext frontends.
- Basic-auth snippets no longer panic when a referenced auth Secret is briefly absent from the render snapshot.
- PrometheusRule default alerts `HAProxyControllerHighQueueDepth` / `HAProxyControllerNoLeader` repointed to metrics the controller actually emits (the old names never fired).
- `networkPolicy.ingress.webhook.from` and `networkPolicy.egress.kubernetesApi` defaults switched to `ipBlock` `0.0.0.0/0` + `::/0`, so the host-network apiserver can reach the webhook on clusters enforcing NetworkPolicy (was silent 502 admission blocks).
- The validating-webhook configuration now sources `watchedResources` from the merged libraries, so library-declared resources are actually validated.
- `features-160-ssl-redirect-map` uses a per-snippet dedup so the map registration and the rule referencing it stay in lockstep under churn.
- `base.yaml` no longer references gateway-library state, restoring the Level-0 resource-agnostic architecture on clusters without Gateway API.
- SPOA mirror plugin no longer flakes the `HTTPRouteRequestMirror` / `MultipleMirrors` / `PercentageMirror` conformance tests (mirror message slots floored at a static minimum; reload drains in-flight dispatches).
- NOTES.txt no longer claims the Gateway API library is enabled when its CRDs are absent (severity downgraded to ℹ️).
- `haproxy.org/pod-maxconn` counts only Running + Ready HAProxy pods.

### Removed

- Dead `spoaHub.podSecurityContext` values key (never consumed — use `haproxy.podSpec.podSecurityContext`).

## [0.1.0] - 2026-03-09

### Added

- Initial Helm chart deploying the controller and HAProxy pods (2 replicas by default)
- Separate controller Service (ClusterIP for operational endpoints) and HAProxy Service (configurable LoadBalancer/ClusterIP)
- Default NetworkPolicy for HAProxy instances
- Leader election support with configurable replica count
- Default SSL certificate configuration via `controller.defaultSSLCertificate`
- Modular template library system with composable libraries merged at Helm render time (enable/disable via `controller.templateLibraries.<name>.enabled`):
  - `base.yaml`: Core HAProxy template structure with extension points
  - `ingress.yaml`: Kubernetes Ingress support (path types: Exact, Prefix, ImplementationSpecific; TLS termination; default backend)
  - `gateway.yaml`: Gateway API support — HTTPRoute and GRPCRoute are watched and routed; traffic splitting, request/response header modification, URL rewrites, and Gateway/Route status patches are emitted. TLS/TCP/UDP listeners are reflected in each Gateway's `supportedKinds` status but TLSRoute/TCPRoute/UDPRoute resources are not watched or routed
  - `haproxytech.yaml`: `haproxy.org/*` annotation compatibility (backend config snippets, SSL passthrough, CORS, basic auth)
  - `ssl.yaml`: TLS/SSL features
  - `haproxy-ingress.yaml`: 56 `haproxy-ingress.github.io/*` annotation compatibility (enabled by default)
- Gateway API status reporting: Gateway conditions (Accepted, Programmed), listener status, HTTPRoute/GRPCRoute parent status with Accepted and ResolvedRefs conditions
- Ingress status reporting: LoadBalancer addresses propagated to Ingress `.status.loadBalancer`
- HAProxy built-in Prometheus exporter enabled by default on the status frontend (`/metrics` on port 8404)
- Grafana dashboard annotations for leader transitions and controller pod starts
- Auto-generated Dataplane API credentials stored in a Secret (deterministic 32-char SHA256 of release-name + namespace; preserved across upgrades from the existing Secret)
- `haproxy.sysctls` for setting kernel parameters on HAProxy pods via pod-level securityContext
- `haproxy.podAnnotations` for custom pod annotations on HAProxy pods (supports Helm template expressions)
- `haproxy.shareProcessNamespace` to enable process namespace sharing between containers (required for signal-based sidecar reload, e.g., SPIFFE/SPIRE mTLS agents)
- `haproxy.shmStats.enabled` to persist stats counters across HAProxy reloads via shared memory (requires HAProxy 3.3+); automatically provisions `/dev/shm` emptyDir volume with auto-calculated size
- `haproxy.nbthread` to control HAProxy thread count (auto-calculated from CPU requests by default)
- `haproxy.dataplane.validateConfig` to control server-side config validation
- `haproxy.dataplane.debugSocketPath` to enable Unix socket for runtime profiling of the Dataplane API sidecar
- `controller.config.dataplane.maxParallel` to limit concurrent Dataplane API operations
- `controller.statusPatches.enabled` to disable status patch writes during migration from another ingress controller
- `extraDeploy` for deploying arbitrary Kubernetes resources alongside the chart (supports Helm templating)
- `extraEnv`, `haproxy.extraEnv`, `haproxy.dataplane.extraEnv` for custom environment variables on all containers
- `global-settings-*`, `defaults-settings-*`, and `frontend-extra-*` extension points for customizing HAProxy global/defaults sections and early frontend directives via template snippets
- `status-patches-*` and `status-extra-*` extension points for custom status and Prometheus endpoint configuration
- `template` post-processor type for declarative output transformations in `postProcessing`
- `guid` directives on all frontends, backends, and servers for stable object identification

### Changed

- Dataplane API credentials consolidated into `credentials.dataplane` section; auto-generated if not provided
- Basic auth userlists are named `auth_<secretNs>_<secretName>` and deduplicated per Secret; each Ingress references its userlist via `http_auth()`. Differs from the official HAProxy Ingress Controller's per-Ingress `{namespace}-{ingressName}` naming so multiple Ingresses sharing the same Secret produce a single userlist (significant speedup for bcrypt hashes)
- Production-ready default resource requests and limits: controller (100m CPU / 512Mi memory), HAProxy (250m CPU / 1Gi memory), dataplane sidecar (50m CPU / 256Mi memory)
- `sidecars`, `extraVolumes`, `extraVolumeMounts` and their `haproxy.*` counterparts support Helm template expressions

### Removed

- `image.appendHaproxyVersion` value (HAProxy version suffix is now always included in controller image tag)
- `haproxy.dataplane.credentials` section (use `credentials.dataplane` instead)
